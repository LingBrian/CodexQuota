# v0.0.33 托盘、显示与查询修复

## 证据和原因

- 本机 v0.0.32 PID 7368 收到 --quit 请求后，发送方退出，但原进程等待 10 秒仍未退出。核对路径后仅终止该旧版进程。
- 已安装 Tauri 2.12.4 源码说明：Windows 上同步命令或事件处理器内创建 WebView 可死锁。原先显示组件、保存设置、托盘开关均可走这条路径；旧 smoke 从异步 Rust 函数创建，未覆盖首次前端 IPC 创建。
- 本机后台日志有一次查询失败，后续连续成功；并发刷新原先会向所有窗口发布 RefreshInProgress 错误，把仍在执行的查询显示成失败。

## 修复

- 显示组件、保存/导入设置、组件菜单改为异步 IPC；托盘开关转入异步任务。异步锁串行化组件创建，避免同时创建同名窗口。
- 托盘和单实例退出统一取消查询，记录 QuitRequested 并设置退出标记；正常退出期间不再拦截主窗口关闭。
- 同时发起的刷新等待并复用同次查询结果；短间隔重试保留真实失败状态，不用旧缓存伪装成功。
- 设置保存不再重复调用一次显示命令；托盘设置错误可传回主界面。

## 验证

- 19 项前端、39 项 Rust 测试通过；1 项依赖登录的 Rust 测试默认忽略。类型检查、构建、fmt、Clippy 通过。
- reports/portable33-ipc/runtime-smoke.json：从隐藏组件起步，真实 WebView IPC 连续显示/隐藏/显示、查询、两项额度、布局及共享退出流程通过。
- reports/portable33-start-visible/runtime-smoke.json：配置启动显示组件的同组回归通过。
- scripts/single-instance.ps1 使用启动显示组件配置，重复启动返回成功、原实例保持，--quit 后原进程在 10 秒内以 0 退出，cleanExit=true。
- 原生点击工具两次初始化均报 trusted Node process exited unexpectedly。本轮没有鼠标点击托盘和截图验收，不将共享退出处理器测试等同于实际点击验证。
