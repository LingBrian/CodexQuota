# 测试开发策略

按红—绿—重构执行：先用测试描述用户可见行为，再写最小实现，最后重构且保持全部测试通过。

| 层级 | 工具 | 覆盖重点 |
|---|---|---|
| Rust 单元 | `cargo test` | 配额计算、设置验证、缓存、通知状态机 |
| Rust 集成 | `cargo test --test` | 文件隔离、CLI fixture、账户事务 |
| Vue 单元 | Vitest | 格式化、剩余额度、组件状态 |
| E2E | Webdriver/Windows VM | 托盘、覆盖层、DPI、Explorer 恢复 |
| 安全 | 静态扫描 | 凭据不得进入日志、构建物或前端 |

新增解析器必须有脱敏真实 fixture 与负向 fixture；“字段缺失”测试必须断言 UI 显示“暂无数据”，不得出现 100%。
